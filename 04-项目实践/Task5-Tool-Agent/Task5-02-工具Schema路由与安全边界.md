# Task 5.2：工具 Schema、路由与安全边界

> [!summary] 必须掌握
> 一个好工具要让模型知道何时用、怎么用、结果代表什么，也要让执行器能校验参数和限制权限。接口描述、实际执行和结果有效性需要分别检查。

返回总览：[[Task5-Tool-Agent学习索引]]

## 1. Schema 描述参数，注册表连接执行

以文件搜索为例，parameters 中可以有多个属性：

```json
{
  "type": "object",
  "properties": {
    "pattern": {"type": "string"},
    "dir": {"type": "string"}
  },
  "required": ["pattern", "dir"],
  "additionalProperties": false
}
```

模型实际提供的是：

```json
{"pattern": "TODO", "dir": "data/agent-fixtures"}
```

`parameters` 是描述参数的 Schema 对象；`properties` 的每个键描述一个参数，`required` 列出必填项。参数本身也可以是数组或嵌套对象。

调用过程为 `工具名与参数 → 解析与校验 → 注册表查找函数 → 工具执行 → 结果反馈`。注册表明确允许调用哪些函数；Schema 本身不会执行任何函数。

## 2. 说明、校验与权限各放在哪里

| 内容 | 合适的位置 |
|---|---|
| 名称、类型、必填字段 | 工具 Schema |
| 适用场景、与其他工具的分工 | 工具描述、system prompt、示例 |
| 缺字段、类型错误、非法取值 | 调用前校验与工具内部检查 |
| 可访问路径、可执行操作、资源额度 | 执行器和运行环境 |
| 结果是否支持最终回答 | 后续决策与独立验收 |

手写版把 Schema 转成 prompt，解析器主要检查参数是 dict，没有统一 Schema validator。`additionalProperties=false` 只有被校验器或支持的后端落实才会产生约束。

这是项目中通用的一课：**配置声明 → 执行路径读取 → 违规输入被拒绝**，三步走完才算限制生效。比如 calculator 虽声明了长度上限，当前入口并没有据此拒绝过长表达式。

## 3. 四个工具各教会了什么

| 工具 | 主要实现思路 | 应当领悟的技巧 |
|---|---|---|
| calculator | AST 解析 + 运算符/函数白名单 | 给确定性工具窄而明确的能力边界；合法 Python 不等于合法数学表达式 |
| python_sandbox | 子进程运行，捕获 stdout，限制超时和 import | 区分程序执行与可见输出；普通脚本需要 print，不会自动回显最后一个表达式 |
| file_search | 路径检查，文件名/内容匹配，返回片段 | 设计好结果语义：命中位置、返回数量、截断标志与总数不能混淆 |
| wiki | 外部查询，语言回退与摘要 | 空结果、网络错误、语言选择是不同状态，需要显式处理 |

几个具体例子足以记住这些区别：

- 搜索结果 `count=20, truncated=true` 只能说明返回了 20 条，不能证明全部命中恰好 20 条。同一文件的文件名和内容都匹配，也只返回一条，命中来源记在 `matched_in`。
- wiki 当前先访问中文站；正常未找到才试英文。英文 query 不会自动切换站点，中文请求抛异常也不会自动进入英文分支。
- Python 没有 print 可能得到空 stdout；wiki 正常返回 None 也可能没有有效事实。**没有异常并不代表结果有用。**
- AST 白名单和 import 限制属于教学级保护；真实不可信代码还需要操作系统层面的权限和资源隔离。截断已捕获的输出，并不能阻止此前大量输出占用内存。

## 4. 返回值也是工具接口的一部分

可以将返回契约改进为以下结构（设计示例，尚未全面实现）：

```json
{
  "ok": false,
  "data": null,
  "error": {"code": "TIMEOUT", "retryable": true},
  "source": null,
  "truncated": false
}
```

成功结果保留数据与来源；失败结果区分超时、参数错误、权限拒绝、没有命中。模型才能分别选择重试、改参数、换查询或停止。`retryable` 提供依据，最终仍要结合预算和副作用决定。

文件和网页内容应作为证据处理；其中的“忽略之前规则”等文本不能扩大工具权限。路径限制还要考虑符号链接和敏感文件，不能只比较原始字符串前缀。

## 5. 自测

1. parameters 是对象，如何声明多参数或数组参数？
	1. 放在properties字段内部
2. Schema、工具描述、注册表和执行器各解决什么问题？
	1. Schema解决工具的整体行为，参数等描述；描述让模型明白工具的概览；注册表用于映射工具函数，执行器直接执行模型
3. 怎样验证一个 max_size 或 timeout 配置真的生效？
	1. 用Mock做越界测试
4. 为什么无异常、空 stdout、未命中、返回被截断，需要分别处理？
	1. 情况不同，无异常正常情况，空stdout需要检查返回码异常流等，未命中；
	2. 如果都只返回空字符串，Agent 无法判断应该：
		- 接受结果；
		- 修改查询；
		- 读取后续内容；
		- 还是重试工具。
5. 一个方便模型使用的工具，除了正确执行，还应返回哪些信息？
	1. 返回有效数据、来源、错误类别和截断信息，必要时附耗时。清晰返回契约让模型更容易决定下一步，也方便程序验收。

### 自测标准答案

> [!success]- 标准答案：1. 在 properties 中描述字段
> 多个键对应多个参数；某个字段可声明为 array 并定义 items。required 列出必须提供的字段，Schema 与实际参数对象要区分。

> [!success]- 标准答案：2. 接口、用途、路由与实际约束
> Schema 描述参数形状，描述说明适用场景，注册表把名称映射到可执行函数，执行器落实校验、权限与资源限制。

> [!success]- 标准答案：3. 沿执行路径检查并测边界
> 找到读取配置的位置，确认执行前或执行中有实际限制，再用越界输入验证被拒绝或终止。仅存在同名字段不算实现。

> [!success]- 标准答案：4. 它们需要不同的补救策略
> 空 stdout 可能要补 print；未命中要调整查询；截断需要补读或独立计数；无异常仍要核对结果是否相关、是否足够。

> [!success]- 标准答案：5. 可解释的状态与证据
> 返回有效数据、来源、错误类别和截断信息，必要时附耗时。清晰返回契约让模型更容易决定下一步，也方便程序验收。
